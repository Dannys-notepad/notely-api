# Notely API Documentation

## Overview

Notely is a JSON REST API for creating, listing, retrieving, updating, and deleting notes. The server mounts the version 1 API at `/api/v1/notes`.

The default server URL is `http://localhost:3000`. Set the `PORT` environment variable to use a different port.

All request bodies must be JSON and should include the header `Content-Type: application/json`.

## Note Object

```json
{
  "id": "a1b2c3d4e5f60708",
  "title": "Meeting notes",
  "content": "Discuss the project timeline.",
  "createdAt": "2026-09-29T12:00:00.000Z",
  "updatedAt": "2026-09-29T12:00:00.000Z"
}
```

`id` is generated by the server. Timestamps are ISO 8601 strings in UTC. `createdAt` is set when a note is created; `updatedAt` changes when it is updated.

## Response Format

Successful API responses and handled errors use this envelope:

```json
{
  "message": "Human-readable result",
  "details": {}
}
```

For unexpected server errors, the response message is `Internal Server Error`; implementation details are not returned to clients.

## Endpoints

### Health Check

`GET /api/v1/notes/health`

Checks that the notes API process is responding. No request body is required.

Success: `200 OK`

```json
{
  "message": "API is up and running",
  "details": { "status": "OK" }
}
```

### Create Note

`POST /api/v1/notes`

Request body:

```json
{
  "title": "Meeting notes",
  "content": "Discuss the project timeline."
}
```

Both fields are required, must be strings, and must contain at least one non-whitespace character. The supplied string values are stored as provided.

Success: `201 Created`

```json
{
  "message": "Note created successfully",
  "details": {
    "note": {
      "id": "a1b2c3d4e5f60708",
      "title": "Meeting notes",
      "content": "Discuss the project timeline.",
      "createdAt": "2026-09-29T12:00:00.000Z",
      "updatedAt": "2026-09-29T12:00:00.000Z"
    }
  }
}
```

Validation failure: `400 Bad Request`

```json
{
  "message": "Title and content must be non-empty strings",
  "details": {}
}
```

### List Notes

`GET /api/v1/notes`

Returns every note. No request body is required. An empty collection is returned as an empty array.

Success: `200 OK`

```json
{
  "message": "Notes retrieved successfully",
  "details": {
    "notes": []
  }
}
```

### Get Note

`GET /api/v1/notes/:id`

Path parameter: `id` is the identifier returned when the note was created. No request body is required.

Success: `200 OK`

```json
{
  "message": "Note retrieved successfully",
  "details": {
    "note": {
      "id": "a1b2c3d4e5f60708",
      "title": "Meeting notes",
      "content": "Discuss the project timeline.",
      "createdAt": "2026-09-29T12:00:00.000Z",
      "updatedAt": "2026-09-29T12:00:00.000Z"
    }
  }
}
```

Unknown ID: `404 Not Found`

```json
{
  "message": "Note not found",
  "details": {}
}
```

### Update Note

`PUT /api/v1/notes/:id`

PUT replaces the note's editable fields. Both `title` and `content` are required and follow the same non-empty-string validation as note creation.

Request body:

```json
{
  "title": "Updated meeting notes",
  "content": "Review the revised project timeline."
}
```

Success: `200 OK`

```json
{
  "message": "Note updated successfully",
  "details": {
    "note": {
      "id": "a1b2c3d4e5f60708",
      "title": "Updated meeting notes",
      "content": "Review the revised project timeline.",
      "createdAt": "2026-09-29T12:00:00.000Z",
      "updatedAt": "2026-09-29T12:05:00.000Z"
    }
  }
}
```

Validation failure: `400 Bad Request`, using the validation error response shown under Create Note. Unknown ID: `404 Not Found`, using the response shown under Get Note.

### Delete Note

`DELETE /api/v1/notes/:id`

Path parameter: `id` identifies the note to delete. No request body is required.

Success: `200 OK`

```json
{
  "message": "Note deleted successfully",
  "details": {}
}
```

Unknown ID: `404 Not Found`, using the response shown under Get Note.

## Other Routes and Errors

`GET /` is a basic process health endpoint and returns `200 OK` with `{ "status": "OK" }`.

Malformed JSON is rejected by Express with `400 Bad Request`. Unexpected errors return a generic `500 Internal Server Error` envelope. Requests to an unregistered path are handled by Express's default not-found response.

## Running and Testing

```sh
npm install

```
